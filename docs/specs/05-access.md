# 05. Авторизация и права

Код: `backend/internal/auth/`, `backend/internal/httpapi/middleware.go`, `backend/internal/httpapi/proxy.go`, `backend/internal/mcpserver/auth.go`, `agent/src/api/routers.py`, `agent/src/clients/mcp.py`.
Тесты: `backend/internal/auth/*_test.go`, `backend/internal/httpapi/middleware_test.go`, `backend/internal/httpapi/proxy_test.go`, `backend/internal/httpapi/conversations_test.go`, `backend/internal/onboarding/http_test.go`, `backend/internal/mcpserver/auth_test.go`, `agent/tests/test_chat.py`.

## Цель

AI-buddy учитывает права пользователя: недоступные ему сведения и операции не раскрываются и не выполняются. Права проверяют Go-сервисы по токену. Промпт модели не является защитой: даже если модель попытается запросить чужие данные, сервис их не вернёт.

## Принципы

1. **Один источник личности.** Пользователь определяется только по подписанному JWT. Ни одна ручка и ни один инструмент не принимает `user_id` или `team_id` от клиента или модели.
2. **Проверка в сервисе.** Каждый запрос к данным фильтруется по пользователю или команде из токена прямо в SQL.
3. **Агент без своих прав.** Агент передаёт токен пользователя в MCP-серверы как есть и сам ничего не разрешает.
4. **Секреты отдельно.** Ключ агента, секрет JWT и ключ GigaChat берутся из переменных окружения и в браузер не попадают. Ключ GigaChat есть только у агента (`agent/.env`) и не передаётся ни в промпт, ни в MCP-серверы; JWT пользователя не передаётся в GigaChat.

## Вход

В Авито авторизация уже есть, поэтому прототип имитирует корпоративный SSO: `POST /api/login` с логином тестовой учётки, без пароля. В ответ выдаётся JWT.

| Параметр | Значение |
|---|---|
| Алгоритм | HS256; `alg=none` и подмена алгоритма отклоняются |
| Секрет | `JWT_SECRET`, не короче 32 байт, иначе сервис не стартует |
| Срок | 24 часа, поле `exp` обязательно |
| Содержимое | `user_id`, `team_id`, `role`, `sub`, `iat`, `exp` |

`GET /api/me` берёт свежие данные пользователя из базы, а не из токена.

## Цепочка запроса чата

```
Браузер ──Bearer JWT──▶ api (requireAuth) ──Bearer JWT + X-Agent-Key──▶ agent
                                                                         │ Bearer JWT
                                                                         ▼
                                                     mcp-buddy / mcp-corporate (проверка JWT)
                                                                         │ user_id, team_id из токена
                                                                         ▼
                                                                    PostgreSQL
```

1. `api` проверяет JWT. Без токена или с неверным токеном отвечает 401, причину не раскрывает.
2. Прокси `api → agent` удаляет любой `X-Agent-Key`, присланный клиентом, и ставит свой из `AGENT_KEY`. Токен пользователя передаётся агенту без изменений.
3. Агент в режиме `go` сравнивает `X-Agent-Key` за постоянное время; без верного ключа отвечает 403 ещё до вызова `whoami`.
4. MCP-серверы проверяют тот же JWT тем же секретом и кладут пользователя в контекст инструмента. Без верного токена MCP-сервер отвечает 401 и инструмент не вызывается; если пользователя в контексте всё же нет, инструмент возвращает ошибку `unauthenticated`.
5. Внутренние ручки хранилища для агента (`/internal/agent/*`) требуют одновременно ключ агента и токен пользователя. Пустой ключ на сервере не пускает никого.

## Что видит пользователь

| Данные | Ограничение |
|---|---|
| Чаты и сообщения | только свои; чужой чат даёт 404 |
| Чек-лист | только свои задачи; чужая задача даёт «не найдена»; поставить `done` себе нельзя |
| Запросы на проверку и прогресс стажёров | только у роли `mentor` (остальным 403) и только по своим стажёрам (`mentor_id`); чужая задача даёт 404 |
| Заявки | только свои |
| База знаний | общие документы и документы своей команды |
| Команда | только своя, только имя и роль |
| Служебные сообщения | вызовы инструментов и ответы `tool` в интерфейс не отдаются |

## Роли

| Роль | Что доступно сверх общего |
|---|---|
| `intern` | свой чек-лист: отправить задачу на проверку, отметить «в работе» |
| `mentor` | очередь проверки своих стажёров, принять или отклонить задачу, прогресс своих стажёров |
| `lead` | только общее: профиль, команда, база знаний, чат, заявки |

Роль берётся из токена. Ручки наставника сначала проверяют роль, затем SQL-условие `mentor_id = id наставника`, поэтому наставник другой команды или руководитель чужую задачу не примет. Агент принять или отклонить задачу не может: такого инструмента нет.

## Защита от инъекций

Найденные документы, история и результаты инструментов передаются модели как данные с явным указанием в промпте не выполнять команды из них. Даже если модель всё же выполнит инструкцию из документа, она может вызвать только инструменты текущего пользователя с его токеном.

Явные просьбы показать системный промпт, схемы инструментов или выгрузить внутренний профиль отсекает фильтр `agent/src/chat/scope.py` до модели. Это ограничение поведения, а не механизм авторизации: права по-прежнему проверяют Go-сервисы. Подробно: [docs/assistant-scope.md](../assistant-scope.md).

## Ошибки

| Ситуация | Ответ |
|---|---|
| Нет заголовка `Authorization` | 401 `missing bearer token` |
| Неверный или просроченный токен | 401 `invalid token`, без деталей |
| Неизвестный логин | 401 `invalid login` |
| Неверный ключ агента на `/internal/agent/*` | 401 `invalid agent key` |
| Неверный ключ агента на агенте | 403 `service_unauthorized` |
| Ручка наставника вызвана другой ролью | 403 `forbidden` |
| Агент недоступен | 502 `agent unavailable`; в лог пишутся метод, путь и ошибка без заголовков |

| Критерий | Тест |

| Прокси заменяет `X-Agent-Key` клиента своим и не буферизует поток | `proxy_test.go::TestAgentProxyStreamsAndRewritesHeaders` |
| Внутренние ручки требуют и ключ, и токен | `conversations_test.go::TestRoutingInternalAgentNeedsKeyAndToken` |

## Вне рамок

- Пароли и настоящий SSO: в Авито они уже есть, прототип только имитирует вход.
- Отзыв токенов до истечения срока.
- Права руководителя на данные всей команды: сейчас у роли `lead` нет дополнительных прав.
