# 07. Интерфейс: состояния, ожидание и ошибки

Код: `frontend/src/` (`App.tsx`, `Login.tsx`, `Shell.tsx`, `Home.tsx`, `Chat.tsx`, `api/client.ts`, `api/sse.ts`). На момент написания код в ветке `feature/frontend`.
Тесты: `frontend/src/api/client.test.ts`, `frontend/src/api/sse.test.ts`, `frontend/src/loginScale.test.ts`.

## Цель

Стажёр работает в одном веб-приложении: вход, главная с онбордингом и чат с Buddy. Простые действия отвечают быстрее 1 секунды. Ответ модели может идти дольше, но экран при этом не блокируется: виден статус ожидания, есть таймаут и кнопка «Повторить».

## Экраны

| Экран | Что на нём |
|---|---|
| Вход | Кнопка входа через имитацию корпоративного SSO под тестовой учёткой. Пометка, что данные тестовые |
| Главная | Приветствие, прогресс адаптации, следующий шаг, задачи по этапам, команда |
| Чат | Лента сообщений, поле ввода, статус ответа, «Начать заново» |

Левая колонка с переключением «Главная» и «Чат» общая для обоих экранов. На ширине до 620 px колонка становится верхней панелью.

## Работа с API

Вся сеть идёт через один модуль `api/client.ts`. Компоненты к сети напрямую не обращаются.

| Режим (`VITE_API_MODE`) | Поведение |
|---|---|
| `api` (по умолчанию) | Запросы к Go API. В режиме разработки Vite проксирует `/api` на `VITE_API_URL` (по умолчанию `http://localhost:8080`) |
| `mock` | Без сети: данные из `api/mock.ts`, ответ Buddy заглушкой. Для работы над вёрсткой без бэкенда |

`VITE_API_BASE` задаёт абсолютный адрес API для сборки без прокси. `VITE_DEMO_LOGIN` задаёт тестовую учётку входа (по умолчанию `sasha.intern`).

Токен хранится в `sessionStorage` и живёт до закрытия вкладки. Ответ 401 на любой запрос сбрасывает токен и возвращает экран входа.

## Чат

1. При открытии загружается последний чат пользователя (`GET /api/conversations`, затем `messages?limit=100`). Если чатов нет, показывается пустое состояние с примерами вопросов.
2. Первый вопрос создаёт чат (`POST /api/conversations`, заголовок из первых 60 символов вопроса).
3. Вопрос отправляется в `POST /api/chat` с новым `client_message_id`. Сообщение пользователя появляется в ленте сразу.
4. Пока идёт ответ, показывается индикатор и текст последнего события `status`. Текст ответа дописывается по `text_delta`.
5. Ответ считается готовым только после `done`. `error` или обрыв потока без `done` показывают ошибку и кнопку «Повторить».
6. **Таймаут.** Если от агента нет ни одного события 30 секунд, запрос прерывается и показывается «Buddy долго не отвечает. Попробуй ещё раз.» Таймер сбрасывается на каждом событии.
7. «Начать заново» очищает ленту, следующий вопрос откроет новый чат.
8. При переключении между вкладками лента берётся из кэша, без пустого экрана и без прокрутки с начала.

Тексты ошибок для пользователя:

| Причина | Текст |
|---|---|
| Таймаут | «Buddy долго не отвечает. Попробуй ещё раз.» |
| Сеть, 502, 504, агент недоступен | «Сервер недоступен. Проверь, что бэкенд запущен.» |
| Остальное | «Не получилось получить ответ. Попробуй ещё раз.» |

## Скорость

- Переключение вкладок, ввод, отправка сообщения в ленту и раскрытие панелей работают локально, без ожидания сети.
- Сборка: JS около 240 КБ (75 КБ gzip), CSS около 23 КБ.
- Картинки маскота в WebP.

## Критерии приёмки

| Критерий | Тест |
|---|---|
| Кадры SSE собираются, даже если разрезаны между кусками потока; понимается CRLF | `sse.test.ts` «собирает кадры, разрезанные между кусками потока…» |
| Последний кадр без пустой строки в конце доходит | `sse.test.ts` «последний кадр без пустой строки…» |
| Вопрос создаёт чат и собирает потоковый ответ; второй вопрос идёт в тот же чат, после «Начать заново» в новый | `client.test.ts` «создаёт чат, шлёт вопрос…», «второй вопрос идёт в тот же чат…» |
| Последний чат загружается при открытии, без чатов история пустая | `client.test.ts` «берёт последний чат…», «нет чатов — пустая история…» |
| Несколько сообщений агента склеиваются через пустую строку | `client.test.ts` «несколько сообщений агента склеиваются…» |
| `error` агента, обрыв без `done`, тишина дольше таймаута, 502 и сбой сети дают понятную ошибку | `client.test.ts` «событие error…», «поток оборвался без done…», «агент молчит дольше таймаута…», «прокси вернул 502…», «сеть упала посреди запроса…», «понятные тексты…» |
| 401 сбрасывает сессию и возвращает экран входа | `client.test.ts` «401 на защищённой ручке…», «401 на /api/chat…» |
| Масштаб экрана входа на разных размерах окна | `loginScale.test.ts` |
| Интерфейс отвечает на локальные действия быстрее 1 секунды | Вручную, проверка в браузере |
