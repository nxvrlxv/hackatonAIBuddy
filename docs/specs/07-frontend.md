# 07. Интерфейс: экраны, роли, ожидание и ошибки

Код: `frontend/src/` (`App.tsx`, `Login.tsx`, `Shell.tsx`, `Home.tsx`, `Reviews.tsx`, `Interns.tsx`, `Chat.tsx`, `Markdown.tsx`, `Help.tsx`, `api/client.ts`, `api/sse.ts`), сборка `frontend/Dockerfile`, `frontend/nginx.conf`.

## Цель

Стажёр и наставник работают в одном веб-приложении: вход, главная и чат с Buddy. Простые действия отвечают быстрее 1 секунды. Ответ модели может идти дольше, но экран при этом не блокируется: виден статус, есть таймаут и кнопка «Повторить». Главная не зависит от модели и работает, даже когда агент недоступен.

## Экраны

| Экран | Что на нём |
|---|---|
| Вход | «Войти через Avito ID» (тестовая учётка `sasha.intern`) и «Войти по email» (поле для любого тестового логина). Пометка, что это тестовый прототип |
| Главная стажёра | Приветствие, «Текущие задачи» (до трёх: сначала в работе, затем на проверке, затем следующие), «Мой онбординг» (прогресс и следующий шаг), «Продолжить с Buddy», «Твоя команда» |
| Главная наставника | «Запросы на проверку» от своих стажёров с кнопками «Принять» и «Отклонить», «Мои стажёры» с прогрессом каждого, команда |
| Главная руководителя | Пояснение, что чек-лист ведут стажёры, команда |
| Чат | Лента сообщений с разметкой Markdown, поле ввода, статус ответа, «Начать заново» |
| «Что умеет Buddy» | Окно из меню пользователя: возможности и примеры вопросов; клик по примеру сразу задаёт вопрос в чате |

Левая колонка с переключением «Главная» и «Чат» и меню пользователя («Что умеет Buddy», «Выйти») общая для всех экранов. На ширине до 620 px колонка становится верхней панелью. Обе вкладки смонтированы всегда: уход на главную не обрывает ответ, который ещё печатается.

## Статусы задач на главной

| Статус API | Плашка |
|---|---|
| `todo` | без плашки: и так видно по порядку |
| `in_progress` | «В работе» |
| `in_progress` + `review_comment` | «Нужно доработать» и комментарий наставника |
| `review` | «На проверке», время отправки |
| `done` | «Готово» |

- Клик по задаче открывает чат с заготовкой «Как выполнить задачу «…»?» в поле ввода. Отправляет её пользователь.
- Кнопка-галочка справа от не начатой задачи или задачи «В работе» отправляет её наставнику на проверку. Плашка меняется сразу, затем главная перечитывается.
- Наставник отклоняет задачу через форму в карточке. Комментарий обязателен, до 500 символов, пустой или слишком длинный на сервер не уходит.
- После принятия или отклонения перечитывается прогресс стажёров.
- Главная перечитывается при каждом возврате на вкладку: Buddy мог отправить задачу из чата.

## Работа с API

Вся сеть идёт через один модуль `api/client.ts`. Компоненты к сети напрямую не обращаются.

| Функция | Ручка |
|---|---|
| `login`, `fetchMe` | `POST /api/login`, `GET /api/me` |
| `fetchHome` | `GET /api/me`, `/api/checklist`, `/api/team` параллельно |
| `submitForReview` | `PATCH /api/checklist/tasks/{id}` `{"status":"review"}` |
| `fetchReviews`, `approveTask`, `rejectTask` | `GET /api/reviews`, `POST /api/reviews/{id}/approve`, `/reject` |
| `fetchInterns` | `GET /api/interns` |
| `fetchHistory`, `sendMessage`, `startNewChat` | `/api/conversations…`, `POST /api/chat` (SSE) |

| Режим (`VITE_API_MODE`) | Поведение |
|---|---|
| `api` (по умолчанию) | Запросы к Go API по относительному пути `/api` |
| `mock` | Без сети: данные из `api/mock.ts`, ответ Buddy заглушкой. Для работы над вёрсткой без бэкенда |

Как `/api` попадает на Go API:
- **Docker:** образ `frontend` собирается в `node:25-alpine` и раздаётся `nginx:1.29-alpine` на порту 3000. nginx проксирует `/api/` на `api:8080` без буферизации (`proxy_buffering off`, `proxy_read_timeout 300s`), поэтому поток SSE доходит по кускам. Интерфейс и API на одном адресе, CORS не нужен. Адрес `api` nginx ищет через DNS Docker при каждом запросе, поэтому пересоздание контейнера `api` не ломает прокси.
- **Разработка:** `npm run dev` поднимает Vite на 5173 и проксирует `/api` на `VITE_API_URL` (по умолчанию `http://localhost:8080`).

`VITE_API_BASE` задаёт абсолютный адрес API для сборки без прокси. `VITE_DEMO_LOGIN` задаёт учётку кнопки «Войти через Avito ID».

Токен хранится в `sessionStorage` и живёт до закрытия вкладки. При перезагрузке сессия восстанавливается через `/api/me`. Ответ 401 на любой запрос сбрасывает токен и возвращает экран входа.

## Чат

1. При открытии загружается последний чат пользователя (`GET /api/conversations`, затем `messages?limit=100`). Если чатов нет, показывается пустое состояние с примерами вопросов.
2. Первый вопрос создаёт чат (`POST /api/conversations`, заголовок из первых 60 символов вопроса).
3. Вопрос отправляется в `POST /api/chat` с новым `client_message_id`. Сообщение пользователя появляется в ленте сразу.
4. Пока идёт ответ, в шапке чата показывается текст последнего события `status`, например «Ищу в базе знаний». Текст ответа дописывается по `text_delta` и отображается как Markdown. Сырой HTML из ответа модели не исполняется, ссылки открываются в новой вкладке.
5. Ответ считается готовым только после `done`. `error` или обрыв потока без `done` показывают ошибку и кнопку «Повторить».
6. **Таймаут.** Если от агента нет ни одного события 180 секунд, запрос прерывается и показывается «Повторить». Таймер сбрасывается на каждом событии. Порог большой, потому что пока модель решает, вызвать ли инструмент, событий нет. Порог подбирался под прежнюю локальную модель на CPU (от 40 секунд до 2,5 минут, замер команды); с облачной GigaChat его можно уменьшить после замеров. Таймаут ловит мёртвое соединение, а зависший ход бэкенд освобождает сам через 5 минут.
7. «Начать заново» очищает ленту, следующий вопрос откроет новый чат.
8. При переключении между вкладками лента берётся из кэша, без пустого экрана и без прокрутки с начала.

Тексты ошибок для пользователя:

| Причина | Текст |
|---|---|
| Таймаут | «Buddy долго не отвечает. Попробуй ещё раз.» |
| Сеть, 502, 504, агент недоступен | «Сервер недоступен. Проверь, что бэкенд запущен.» |
| 409: в чате ещё идёт прошлый ответ | «Buddy ещё заканчивает прошлый ответ. Подожди минуту или нажми «Начать заново».» |
| Ошибки проверки задач (404, 409, 422, 400) | «Запрос не найден — возможно, его уже обработали.», «Задачу уже приняли.», «Задачу уже проверили.», «Напиши комментарий для стажёра (до 500 символов).», «Некорректная задача.» |
| Остальное | «Не получилось получить ответ. Попробуй ещё раз.» |

## Скорость

- Переключение вкладок, ввод, отправка сообщения в ленту, отправка задачи на проверку и раскрытие окон работают локально, без ожидания сети: результат виден сразу, затем данные сверяются с сервером.
- Сборка на 14.11: JS около 426 КБ (131 КБ gzip), CSS около 35 КБ (8 КБ gzip).
- Картинки маскота в WebP.
