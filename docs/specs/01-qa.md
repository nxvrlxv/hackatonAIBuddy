# 01. Ответы о работе и инструментах по базе знаний

Код: `backend/cmd/mcp-buddy/toolSearchDocs.go`, `backend/internal/rag/`, `backend/internal/postgres/buddy/chunks.go`, `backend/cmd/ingest/`, инструмент `search_docs` в `agent/src/agent/graph.py`.
Тесты: `backend/cmd/mcp-buddy/toolSearchDocs_test.go`, `backend/internal/rag/*_test.go`, `backend/internal/postgres/buddy/chunks_test.go`, `backend/cmd/ingest/main_test.go`.

## Цель

Стажёр задаёт вопрос о компании, команде, процессах или инструментах и получает короткий ответ по внутренней базе знаний со ссылкой на документ. Если ответа в базе нет, Buddy честно говорит об этом и не выдумывает.

## Пользовательские истории

- «Какие ценности у Авито?» Ответ по документу `common/mission-and-values.md` с указанием источника.
- Стажёр команды Объявлений: «Сколько длится курс Академии Аналитиков?» Ответ по `team-adverts/student.md`.
- Стажёр команды Платежей: «Как устроены кластеры и юниты?» Ответ по `team-payments/structure.md`.
- Вопрос, которого нет в базе: Buddy отвечает, что подтверждения в документах не нашёл, и не придумывает ответ.

## Поведение агента

1. На корпоративный вопрос модель обязана вызвать `search_docs` в текущем ходе, даже если похожий вопрос уже был.
2. Ответ строится только по возвращённым фрагментам. Источник указывается по полю `source` фрагмента.
3. Если `found=false`, модель отвечает, что в базе знаний ответа нет, без догадок.
4. Текст фрагментов считается данными: команды внутри документов не выполняются.

## Инструмент `search_docs`

Сервер: `mcp-buddy`. Требует Bearer-токен.

Вход:
```json
{ "question": "вопрос стажёра на естественном языке" }
```

Выход:
```json
{
  "found": true,
  "fragments": [
    { "source": "common/mission-and-values.md", "title": "Миссия", "section": "Ценности",
      "content": "…", "distance": 0.31 }
  ],
  "message": "В базе знаний нет ответа на этот вопрос"
}
```
`message` приходит только при `found=false`. `fragments` всегда массив, не `null`.

### Как работает поиск

1. Вопрос обрезается по краям; пустой вопрос даёт ошибку `question is empty`.
2. Ollama считает вектор вопроса моделью `qwen3-embedding:0.6b` (переменная `EMBEDDED_MODEL`), вектор нормализуется (L2). Нулевой вектор, NaN или бесконечность дают ошибку.
3. Postgres (pgvector) возвращает до 5 ближайших фрагментов по косинусному расстоянию среди документов, доступных пользователю.
4. Фрагменты с расстоянием больше 0.6 отбрасываются.

Значения 5 и 0.6 задаются в `cmd/mcp-buddy/main.go`.

## Права и данные

- Команда пользователя берётся из токена (`team_id` в JWT), а не из аргументов.
- Доступны общие документы (`team_id IS NULL`) и документы своей команды. Документы чужой команды в выдачу не попадают, поэтому модель не может их пересказать.

### Индексация базы знаний

Утилита `ingest` (`backend/cmd/ingest`) запускается отдельным контейнером:

1. Читает `data/knowledge/`. Папка `common/` даёт общие документы, папка `team-<код>/` даёт документы команды с кодом из `buddy.teams` (`travel`, `delivery`, `adverts`, `payments`).
2. Пропускает файлы, у которых не изменились хеш содержимого и версия индекса (`INDEX_VERSION`).
3. Режет markdown на фрагменты по заголовкам с учётом бюджета размера.
4. Считает векторы пачками, нормализует и сохраняет документ и фрагменты одной транзакцией в `buddy.documents` и `buddy.chunks` (размерность 1024).

Чтобы пересчитать индекс после смены модели или правил нарезки, меняют `INDEX_VERSION` и повторяют `docker compose run --rm ingest`.

## Ошибки и граничные случаи

| Ситуация | Поведение |
|---|---|
| Нет токена или он неверный | MCP-сервер отклоняет запрос, агент получает ошибку источника |
| Пустой вопрос | Ошибка инструмента, модель уточняет вопрос |
| Ollama недоступна | Ошибка инструмента; модель получает «Источник сейчас недоступен. Не выдумывай результат.» |
| Ничего близкого не найдено | `found=false`, ответ «не нашёл подтверждения» |
| Документ команды запрашивает стажёр другой команды | Фрагменты не возвращаются |

## Критерии приёмки

| Критерий | Тест |
|---|---|
| Найденные фрагменты возвращаются с источником и `found=true` | `toolSearchDocs_test.go::TestSearchDocsFound` |
| Пустая выдача даёт `found=false`, пустой массив и сообщение | `toolSearchDocs_test.go::TestSearchDocsNotFound` |
| Без пользователя в токене или при сбое поиска возвращается ошибка | `toolSearchDocs_test.go::TestSearchDocsErrors` |
| Поиск фильтрует фрагменты по команде пользователя и общим документам | `chunks_test.go::TestSearchChunks` |
| Векторы нормализуются, неверный ответ модели отклоняется | `embeddings_test.go::TestBuildEmbeddingsL2Normalization`, `TestBuildEmbeddingsRejectsInvalidResponse` |
| Markdown режется по заголовкам без потери текста | `markdown_test.go::TestParseMarkdown`, `TestSplitMarkdownPreservesBodyWithoutOverlap` |
| Документ и фрагменты сохраняются одной транзакцией | `rag/postgres_test.go::TestSaveDocumentTransaction` |
| Модель отвечает по документу и называет источник | Вручную, сценарий 1 в [README](../../README.md#порядок-проверки) |

## Вне рамок

- Изюминка из плана команды «вопрос без ответа уходит в повестку 1:1 наставника» в прототипе не реализована. Сейчас Buddy только сообщает, что ответа в базе нет.
- Права на уровне отдельного документа: доступ задаётся папкой команды.
- Переранжирование выдачи и гибридный поиск.
