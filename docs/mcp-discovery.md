# Динамические MCP-инструменты

На каждом ходе агент запрашивает tools/list у MCP_URL и MCP_CORPORATE_URL
с Authorization пользователя, проходя все страницы nextCursor.
Описание и JSON Schema приходят от серверов, затем преобразуются в StructuredTool.
Исполнение использует URL, с которого инструмент был получен. Новые инструменты
на подключённых серверах не требуют Python-обёртки или перезапуска агента.
Между пользователями список не кешируется. Изменение списка во время хода
будет видно со следующего хода; уведомления tools/list_changed пока не используются.
Одинаковые имена на разных серверах отклоняются с mcp_duplicate_tool_name:
имена должны быть уникальны. Недоступность discovery не подменяется статическим списком.

## Политики приложения
- whoami вызывается кодом перед графом на MCP_URL, не предлагается модели.
- create_time_off_request: idempotency_key скрыт от модели и подставляется из run_id.
  Причина обязательна: при пропуске или пробельной строке инструмент просит уточнение,
  не вызывает сервер. Причина должна совпадать с фрагментом пользовательского сообщения в доступной истории или текущем ходе. Если история была сокращена, агент попросит повторить причину.
- update_task_status сохраняет прежнюю проверку сообщения о выполнении задачи и поиск
  по названию: серверный task_id в схеме адаптируется к строковому task.
- search_history остаётся локальным инструментом памяти, а не MCP.
- RAM demo сохраняет локальный search_docs. Рабочий go-режим использует discovery.
- Токен находится в транспортном замыкании, не в аргументах модели.

## Отгулы
0009_time_off_reason меняет шаблон в БД: reason.required=true.
Go отклоняет новую заявку без непустой причины; старые заявки остаются доступны,
повтор старой заявки с тем же ключом сохраняет прежнюю семантику идемпотентности.
Отдельного подтверждения / interrupt по-прежнему нет.
Пример: «Оформи отгул на 20 ноября» -> вопрос о причине -> «По семейным обстоятельствам»
-> создание с датой из истории.
