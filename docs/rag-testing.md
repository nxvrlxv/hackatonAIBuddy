# Проверка чата и RAG

Все команды выполняются из корня проекта в WSL/Linux.

## Открыть настоящий чат

Запуск:
```bash
docker compose up --build -d api mcp-buddy agent
```

Откройте http://localhost:8001/demo.
Это тестовая HTML-страница, которая в режиме go обращается к публичному Go API
http://localhost:8080: входит по тестовой учётке, создаёт чаты, показывает историю
и получает SSE через /api/chat. Она не передаёт сервисный X-Agent-Key браузеру.

Выберите пользователя, нажмите «Новый чат» и отправьте вопрос.
Токен хранится только в памяти страницы; после перезагрузки выполняется новый вход.
В режиме demo эта же страница использует учебных пользователей и RAM-хранилище.
Это временный интерфейс проверки, не полноценный фронтенд.

PUBLIC_GO_API_URL — адрес Go, доступный браузеру. GO_API_URL — внутренний адрес Go
для Python; внутри Compose это http://api:8080.
Для локального браузера PUBLIC_GO_API_URL=http://localhost:8080.
При доступе с другого компьютера укажите доступный с него адрес Go.

## Проиндексировать документы

```bash
docker compose run --rm ingest
```

Отдельный контейнер ingest запускает /app/ingest -iv <INDEX_VERSION>.
Папка data/knowledge монтируется в него как /data/knowledge только для чтения.
Вручную входить в контейнер не требуется.

Последовательность:
1. Выбирает новые/изменённые файлы по хешу и INDEX_VERSION.
2. Разбивает текст на связные фрагменты с заголовками.
3. Вызывает qwen3-embedding:0.6b через Ollama.
4. Нормализует векторы и сохраняет документ/чанки транзакцией.
5. Записывает данные в buddy.documents и buddy.chunks.

Повторный запуск без изменения документов обычно пишет selected=0.
Для смены embedding-модели/правил чанкинга измените INDEX_VERSION и повторите ingest.
Новые файлы кладите в data/knowledge/common либо data/knowledge/team-<код команды>.
Папка команды должна соответствовать коду в buddy.teams.

На проверенном наборе проекта: 3 документа, 26 чанков, размерность каждого вектора 1024.

## Проверить сохранение в БД

Для стандартных POSTGRES_USER=buddy и POSTGRES_DB=buddy:
```bash
docker compose exec postgres psql -U buddy -d buddy -c "SELECT source_path, indexing_version FROM buddy.documents;"
docker compose exec postgres psql -U buddy -d buddy -c "SELECT count(*) AS chunks, min(vector_dims(embedding)), max(vector_dims(embedding)) FROM buddy.chunks;"
```

Если изменили имя пользователя/БД в .env, подставьте их значения.
Ожидается ненулевое количество чанков и размерность 1024.

## Проверить поиск и ответ

В HTML-чате:
- Саша (Путешествия): «Найди через search_docs три ценности Авито. Укажи источник».
  Источник — common/mission-and-values.md.
- Пётр (Объявления): «Сколько длится курс Академии Аналитиков Авито? Найди в базе знаний».
  Источник — team-adverts/student.md.
- Ольга (Платежи): «Как устроены кластеры и юниты? Найди в базе знаний».
  Источник — team-payments/structure.md.

Модель вызывает search_docs, Go вычисляет embedding вопроса и ищет по общим
документам и документам команды из проверенного токена.
Результат инструмента с источниками возвращается LLM; она формирует ответ.
Документы учебные и могут содержать устаревшие сведения.

Проверить, что использовался инструмент, а не только знания модели:
```bash
docker compose exec postgres psql -U buddy -d buddy -c "SELECT conversation_id, sequence_number, role, payload->'tool_calls' AS calls, payload->>'tool_call_id' AS call_id FROM buddy.messages ORDER BY id DESC LIMIT 20;"
```
В последовательности должны быть assistant с search_docs, tool с соответствующим
tool_call_id и финальный assistant. Фронтенд служебные сообщения скрывает.

## Порты и настройки памяти

Ollama: http://localhost:11434 с компьютера, http://ollama:11434 внутри Compose.
Модели хранятся в ollama_data и переживают пересоздание контейнера.

Локальный стенд ограничивает одновременную загрузку моделей:
OLLAMA_MAX_LOADED_MODELS=1, OLLAMA_NUM_PARALLEL=1.
Диалоговая и embedding-модель загружаются по очереди; это экономит память,
но переключение добавляет задержку.
Размер контекста агента задаёт CONTEXT_TOKENS.
В примерах используется 8192, но agent/.env переопределяет одноимённые значения
корневого .env. Изменив настройки, пересоздайте нужный контейнер:
```bash
docker compose up -d --no-deps agent
docker compose up -d --no-deps ollama
```
Не пересоздавайте их во время активного ответа.

## Что пока не включено

HISTORY_SEARCH_ENABLED=false — поиск по прошлым чатам не реализован в текущем Go.
SUMMARY_ENABLED=false — резюме не сохраняется; старые целые ходы убираются только
из контекста, а полная история остаётся в БД.
Это не мешает RAG по корпоративным документам.
Чек-листы и отгулы не подключены как инструменты этого графа.

Срок активности run — 5 минут без записи. При длительной остановке компьютера,
сбое процесса или зависшем внешнем вызове ход может быть прерван. Новый запрос
отправляется с новым client_message_id.

## Миграции

Служебная таблица версий закреплена за public.schema_migrations.
Это предотвращает попытку заново применить миграции после появления схемы buddy,
совпадающей с именем PostgreSQL-пользователя. Повторный запуск мигратора успешен
и не удаляет существующую историю.
