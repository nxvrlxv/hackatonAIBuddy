# Апрув задач онбординга наставником — контракт

Общий контракт для бэкенда (Go), фронта и агента. Меняется только по договорённости всех трёх сторон.

## Сценарий

1. Стажёр сообщает Buddy, что выполнил задачу («я получил доступ к GitLab»), или нажимает «Отправить на проверку» на главной.
2. Задача переходит в статус `review` («на проверке»). `done` стажёр поставить себе не может.
3. У наставника этого стажёра (`users.mentor_id`) на главной появляется запрос в блоке «Запросы на проверку».
4. Наставник нажимает **Принять** → задача `done`, прогресс стажёра растёт.
   Или **Отклонить** с обязательным комментарием → задача `in_progress`, комментарий виден стажёру и Buddy.
5. Статусы меняет **бэкенд по действию наставника**. Модель только посредник: создаёт запрос через инструмент и пересказывает результат.

## Статусы задачи

| Статус | Кто ставит | Смысл | В прогрессе |
|---|---|---|---|
| `todo` | система | не начата | нет |
| `in_progress` | стажёр; бэкенд при отклонении | в работе / нужно доработать | нет |
| `review` | стажёр (запрос `done` тоже превращается в `review`) | отправлена наставнику | **нет** |
| `done` | **только наставник** (approve) | принята | да |

`next` в чек-листе — первая задача в статусе `todo` или `in_progress` (задачи на проверке пропускаются).

## Объект задачи (в `GET /api/checklist`, `PATCH`-ответе и MCP `get_checklist`)

```json
{
  "id": 42,
  "title": "Доступ к GitLab",
  "description": "Оформи заявку на доступ к GitLab и репозиториям команды.",
  "status": "review",
  "completed_at": null,
  "submitted_at": "2026-11-15T10:12:00Z",
  "review_comment": null
}
```

- `submitted_at` — когда отправлена на проверку (есть, пока статус `review`).
- `review_comment` — комментарий наставника при последнем **отклонении**. Есть, когда задачу вернули (`in_progress`); очищается при следующей отправке и при принятии.
- Новые поля в JSON с `omitempty`: старые клиенты не ломаются.

## HTTP (Go api, все за `requireAuth`, пользователь — из токена)

### Стажёр

`PATCH /api/checklist/tasks/{id}` body `{"status": "todo" | "in_progress" | "review" | "done"}`
- `done` от стажёра сохраняется как `review` (ответ показывает фактический статус).
- Повторная отправка задачи, которая уже в `review`, — идемпотентна: `200`, ничего не меняется, `submitted_at` прежний (очередь у наставника не перемешивается).
- Задачу в `done` менять нельзя → `409 {"error":"task already approved"}`.
- Ответ `200 {"task": Task, "progress": {"done", "total", "percent"}}` — как сейчас.

### Наставник

`GET /api/reviews` → `200`
```json
{
  "reviews": [
    {
      "task_id": 42,
      "task_title": "Доступ к GitLab",
      "task_description": "Оформи заявку…",
      "stage_title": "Доступы и инструменты",
      "intern": { "id": 3, "full_name": "Саша Иванов" },
      "submitted_at": "2026-11-15T10:12:00Z"
    }
  ]
}
```
Только задачи в `review` у стажёров, чей `mentor_id` = текущий пользователь; старые сверху.
Все три ручки проверки — только для роли `mentor` из токена: остальным `403 {"error":"forbidden"}` (фронт их и не вызывает).

`POST /api/reviews/{task_id}/approve` (без тела) → `200 {"task_id": 42, "status": "done"}`

`POST /api/reviews/{task_id}/reject` body `{"comment": "Нет доступа к репозиторию команды"}` → `200 {"task_id": 42, "status": "in_progress"}`
- `comment` обязателен, 1–500 символов после trim → иначе `422 {"error":"comment is required"}`.

Ошибки approve/reject:
- `404 {"error":"not found"}` — задачи нет или стажёр не твой (не раскрываем, что задача существует).
- `409 {"error":"task is not in review"}` — уже принята/отклонена/не отправлялась.
- `400 {"error":"invalid task id"}`.

## MCP (mcp-buddy, инструменты онбординга)

`update_task_status(task_id, status)` — без изменения сигнатуры. Для стажёра `done` → `review`.
Ответ: `{"task": Task, "progress": …}` — модель видит `status: "review"`.
Ошибки — коротким машинным текстом, который агент пересказывает без догадок: `task already approved`, `task not found`.

`get_checklist` — задачи с новыми полями `submitted_at`, `review_comment`.

Агенту: `review` = «отправлено наставнику на проверку», **не** «выполнено». Принять/отклонить через чат нельзя — только кнопками наставника.

## Тексты для UI

| Статус | Плашка у стажёра |
|---|---|
| `review` | «На проверке» |
| `in_progress` + `review_comment` | «Нужно доработать» + комментарий наставника |
| `in_progress` | «В работе» |
| `done` | «Готово» |
